# BUG-2D674B04 — No permite crear solicitud con motivo Avería Mecánica

SIT, prioridad alta. Reporta Ian Téllez (17 nov 2026); asignado a Joshua Morin.
Avería mecánica no lleva siniestro: al «Enviar solicitud» aparece «No se encontró ningún siniestro o póliza [HTTP 404]».

## Evidencia (logs GCP, 17 nov 2026 15:21:53 UTC)
- El micrositio de test (`morfeo-test`, servicio `micrositio-autorelevo-web`) hace proxy de `/k2portal` al backend de
  **dev**: `K2_PORTAL_TARGET=https://morfeo-dev-321917.ue.r.appspot.com`, versión `micrositio-autorelevo`. Los logs de la API están en dev.
- Póliza `Q2|50027051` sin inciso. `POST …/auto-relevo/tickets` 404 → `POST /api/assistancechubb/sales?typeSearch=3` 500.
- Chubb SIT (`Policy/SubstituteExp`): `400 $.NumeroInciso: The JSON value could not be converted to System.Int32`.
  El respaldo `abaqa …/Api.ConsultaCobertura` devolvió 502 → «No se encontró ningún siniestro o póliza».

## Causa
`captura-info.component.ts:413` crea el ticket con `polizaK2(sess.numPoliza)` **sin inciso**. Sin siniestro, Flask
consulta a Chubb por póliza (`_fetch_chubb`, `typeSearch=3`) y manda `NumeroInciso: ""` (`inciso or ""`).
Con siniestro usa `typeSearch=9` y el inciso no importa; por eso solo falla avería mecánica.
`num-siniestro.component.ts:276` ya arma `${polizaK2(...)}|${sess.inciso}`.

## Fix aplicado (18 nov 2026, micrositio `dev`, sin commit)
Micrositio, `captura-info.component.ts:413`: `const poliza = \`${polizaK2(sess.numPoliza)}|${sess.inciso}\`;`
(mismo formato que num-siniestro; `_parse_policy_parts` ya acepta `PREFIJO|NUMERO|INCISO`).
Opcional en Flask: no mandar `NumeroInciso` vacío como string.

Lo de Codex (columnas NOT NULL para `numero_siniestro`/`sinister_chubb_id`) no apareció en los logs: fue 404 antes de guardar.
Puede aparecer después del fix; hay que probar en dev.
